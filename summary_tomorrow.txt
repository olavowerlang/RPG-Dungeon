[C] Clone AI jittery movement + health bar not showing at correct speed
    TWO separate issues:
    1. JITTER: Every FixedUpdate does `_rb.velocity += knock` even when
       KnockbackVelocity is near-zero. Tiny floating point additions accumulate
       and fight with _impulseVelocity decay. Fix: only add knockback if
       knock.magnitude > 0.05f threshold.
    2. BAR SPEED: revealDuration is a [SerializeField] — Unity saves the old
       value (1.6) in the scene even after changing code default to 3.1. User
       must manually type 3.1 in the Inspector field on the BossHealthBarUI
       component and hit Enter. If that still doesn't work, force it in Awake:
       add `if (revealDuration < 2f) revealDuration = 3.1f;` as a safety guard.

[C] PigShopkeeper (instance 3) click does nothing
    Code. Has been attempted multiple times. Most likely root cause: mainDialogue

    Debug steps: add a Debug.Log in OnTriggerEnter2D to confirm it fires, and

[C] Cave pig not sleeping / wake animation not firing

[C] Enemies not taking damage + clone quip lines not appearing + jittery movement
    THREE things bundled, likely appeared together after the DamageDealer lazy
    init change (added to fix CloneAnimator.Awake NullRef).

    1. DAMAGE BUG — Suspect: DamageDealer.BeginSwing() now does
       `if (Col != null) Col.enabled = true`. If Col returns null (GetComponent
       finds no Collider2D on the hitbox child), the hitbox silently never enables.
       Previously this would have thrown a NullRef loudly. Check: does the player's
       hitbox child still have a Collider2D component? If it was accidentally
       removed, re-add it. If Col is fine, the bug might be elsewhere.
       Quick test: add Debug.Log("BeginSwing col=" + Col) to confirm.

    2. QUIP LINES NOT APPEARING — CRUCIAL. These lines are a core part of the
       boss fight personality and must work. CloneFightingLines is NOT a Canvas
       UI element. It's a world-space TextMeshPro auto-created at runtime as a
       child of the Clone root. The component must be added to the Clone root
       GameObject in the editor. CloneAI.Start() does
       GetComponent<CloneFightingLines>() — if the component isn't on the same
       GameObject, _fightingLines is null and StartLines() is never called.
       Nothing to build in Canvas. Fix: add CloneFightingLines component to the
       Clone root in the inspector. Lines fire every 6-13s once StartFight() is
       called. The label auto-creates itself above the clone's head at runtime.

    3. JITTER ON NORMAL ENEMIES — same root cause as clone jitter above
       (knockback accumulation in FixedUpdate). Fix is the same threshold check.
